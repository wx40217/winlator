# Winlator 第一版游戏库改造方案

本方案按用户授权，对未决项采用推荐答案。它是实现前的范围与交互方案，不代表 App 已修改或通过实机验收。

## 决策结果

| 决策 | 推荐结果 | 原因 |
| --- | --- | --- |
| 用户 | 自己和有基本折腾能力的玩家 | 用户已明确选择 |
| 第一条流程 | 找到游戏 → 启动 → 再次启动 | 用户已明确选择 |
| 流程起点 | 已有快捷方式 | 先改善日常使用，控制安装和兼容性流程范围 |
| 主要设备 | 手机竖屏浏览，游戏横屏运行 | 浏览与运行分别适应任务，浏览页兼容横屏和大屏 |
| 内容组织 | 游戏库为默认首页；容器与设置仍可直接进入 | 日常操作优先，底层能力保持可达 |
| Windows 非游戏程序 | 保留并允许启动 | 不根据名字自动判断或隐藏程序 |
| 点击规则 | 点击整个条目启动；更多按钮打开操作；长按不是唯一入口 | 修复当前文字、空白与图标点击命中不一致 |
| 查找方式 | 名称搜索、全部/收藏切换、容器筛选 | 复用真实数据，避免臆测游戏类型和兼容性 |
| 显示方式 | 图标网格默认，可切换紧凑列表 | 网格易辨认，列表适合大量游戏和长标题 |
| 目录 | 保留真实目录；显示路径并支持返回上级；最近和收藏跨目录展示 | 不重写或移动用户的快捷方式文件 |
| 默认排序 | 全部按名称排序；最近启动按时间降序 | 规则明确，避免主页反复无预期重排 |
| 最近信息 | 最近启动，最多展示 5 项 | 记录启动动作，不误称运行成功或恢复存档 |
| 收藏 | 本地收藏标记，既有文件管理器 Favorites 保持原语义 | 不能把目录当作已存在的游戏收藏模型 |
| 再次启动 | 点击最近项目重新执行现有启动链路 | 当前运行能力不支持承诺继续上次进度 |
| 设置范围 | 明确显示所属容器；沿用游戏设置入口 | 不在第一版重写容器设置和配置引擎 |
| 退出返回 | 恢复搜索、筛选、目录、视图方式及浏览位置 | 当前退出会重启 App，状态必须持久保存 |
| 图片 | 使用已有程序图标，缺失时显示统一占位图标 | 无联网封面识别、无未经证实的匹配 |
| 视觉 | Android 原生布局，蓝色调导航表面、清晰文字和克制密度 | 适合操作型产品，浅色/深色跟随系统 |
| 构建方式 | code-first，保持 Java/XML 原生技术栈 | 用真实交互验证方案，不做框架迁移 |
| 发布 | 先提交可审阅的源码和调试 APK；是否发布版本另定 | 先证明交互和兼容性 |

## 核心流程

1. 打开 App 默认进入游戏库。正常加载已有快捷方式；首屏先展示真实的最近启动记录，再展示全部项目。没有历史时直接展示全部项目，不制造示例记录。
2. 搜索名称或按容器筛选；收藏入口只显示真实的本地收藏。标题允许两行；列表保留可辨认的所属容器与目录信息。
3. 点击整个项目执行已有启动链路；更多按钮单独命中，打开游戏操作与现有设置入口。防止连续点击造成重复启动请求。
4. 在执行跳转前保存浏览上下文并记录最近启动动作。未找到目标文件或容器时明确指出问题，提供现有配置/管理入口；不无条件显示成功。
5. 退出运行环境后，App 重启并恢复浏览上下文。目标项目已被删除、目录消失或筛选结果变化时回退到安全位置，不阻止进入首页。

## 关键状态

- 首次加载：保持布局稳定，必要时显示加载状态；读取结果后替换。
- 无快捷方式：显示“还没有可启动的程序”，引导进入已有容器和文件管理流程；不声称第一版有自动导入功能。
- 搜索/筛选无结果：保留条件并提供清除操作；不当作整个库为空。
- 无最近记录、无收藏：不填充演示数据；收藏页解释可从更多菜单添加。
- 名称很长、图标缺失、项目很多：分别通过两行标题、统一占位图标、RecyclerView 与后台读取处理。
- 文件或容器失效：显示可理解的错误；保留记录供用户处理，不擅自删除文件。
- 横屏、大字体、深色模式：内容重新排布，控件不裁切，系统返回和触控目标保持可用。

## 数据与实现边界

快捷方式文件、容器参数和启动协议保持既有格式。新增元数据存放在 App 本地，以稳定标识关联已有快捷方式；标识的具体实现须依据当前 Shortcut UUID/路径能力选定，避免同名或不同容器之间串数据。旧数据升级后直接可用，缺失元数据默认未收藏、无历史。

目录和快捷方式重命名、移动、复制、删除时必须明确关联记录的生命周期：重命名或移动保留原项目历史；复制视为独立项目；删除仅清理该项目的元数据。实现时检查当前文件操作回调，不能把“移动导致路径变化”误判为新项目。

第一版不扩展首次安装引导、兼容性自动调参、联网封面库、游戏中菜单、触控编辑、游玩时长、即时存档或容器配置重做。保留这些能力的既有入口。

## 视觉方向比较

Operate 模式：世界只影响字体、配色、密度及一个明确的状态反馈；导航和控件采用 Android 原生习惯。方向探索种子：88d1c4f4。

七个候选：原生媒体库、藏品索引、掌机游戏架、游戏说明书、收藏目录、实体游戏盒、游戏杂志清单。采用分配的第五个“收藏目录”：蓝色调导航、清晰的项目图标与标题、紧凑的容器归属信息；一次启动后，该项目进入最近启动区，同时浏览条件保持不变。这一状态变化是主要反馈，不增加装饰动画。

| 对照方向 | 用户认同/任务清晰度判断 | 结论与吸收的设计纪律 |
| --- | --- | --- |
| 数据条码场 | 游戏身份和启动动作不够清晰 | 不采用；保留高对比状态识别 |
| 登机牌与航班板 | 排序稳定易懂，但航班分区不适合游戏操作 | 不采用；保留更新时条目身份与上下文稳定 |
| 时刻表斜排幻灯片 | 倾斜材质与单一字号增加手机阅读成本 | 不采用；保留密度可调和优先级排布 |
| 设计年鉴图版 | 对齐纪律好，强依赖图版和归属标记 | 不采用；保留图标、标题、操作区域严格对齐 |
| 分页软件手册 | 专业认同较强，但视觉层数干扰直接启动 | 不采用；保留设置分层、默认与覆盖范围明确 |
| 流媒体海报墙 | 游戏浏览认同强，但真实海报素材不足，多轴滚动增加触屏负担 | 不采用；保留聚焦当前项目和清楚的主操作 |

## 验收结果应包含什么

- 代码层：旧快捷方式能正常读取并走同一启动链路；新增元数据有稳定隔离、合理迁移和文件操作生命周期处理。
- 交互层：名称、图标、空白区域点击结果一致；更多按钮不误启动；搜索、收藏、筛选和视图切换有效。
- 返回层：退出导致进程重启后，浏览条件与位置恢复；不存在的目标安全回退。
- 界面层：手机竖屏/横屏、浅色/深色和大字体截图；正常、空、筛选无结果、长标题状态。
- 运行层：有合适设备与已有可运行程序时，验证真实启动和退出；没有对应设备或程序时明确报告未验证，不用界面预览替代。
